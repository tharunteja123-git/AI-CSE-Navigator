# DSA Guide for Placements — CSE Students India

## Why DSA Matters
- Service companies (TCS, Infosys): Basic DSA + aptitude
- Mid-tier product (Zoho, Freshworks): Medium DSA
- Top product (Flipkart, Amazon, Google): Hard DSA + System Design

## Topic Roadmap (order matters)

### Phase 1 — Basics (3-4 weeks)
1. **Arrays** — traversal, two pointers, sliding window
2. **Strings** — manipulation, palindrome, anagram
3. **Math** — prime, GCD, modular arithmetic
4. **Recursion** — base case, tree of calls, backtracking basics

### Phase 2 — Core DSA (4-6 weeks)
5. **Sorting** — bubble, selection, insertion, merge, quick
6. **Searching** — binary search (all variants)
7. **Linked Lists** — singly, doubly, cycle detection, reversal
8. **Stack & Queue** — implementation, monotonic stack, BFS

### Phase 3 — Intermediate (4-6 weeks)
9. **Trees** — binary tree, BST, traversals (inorder, preorder, postorder)
10. **Heaps/Priority Queue** — min/max heap, top-k problems
11. **Hashing** — HashMap, HashSet, frequency counting
12. **Greedy** — activity selection, interval scheduling

### Phase 4 — Advanced (4-8 weeks)
13. **Dynamic Programming** — memoization, tabulation, classic problems
14. **Graphs** — BFS, DFS, Dijkstra, topological sort, Union Find
15. **Tries** — prefix matching, autocomplete
16. **Segment Trees** — range queries (optional for most companies)

## LeetCode Target by Company Type
- Service companies: 50 easy problems
- Mid-tier product: 100 easy + 50 medium
- FAANG/unicorns: 200+ problems (easy + medium + some hard)

## Top 10 Must-Know Patterns
1. Two Pointers
2. Sliding Window
3. Fast & Slow Pointers (Floyd's cycle)
4. Binary Search on answer
5. BFS for shortest path
6. DFS + backtracking
7. Dynamic Programming (0/1 knapsack, LCS, LIS)
8. Monotonic Stack
9. Union Find (Disjoint Set)
10. Topological Sort

## Interview Tips
- Always clarify constraints before coding
- Think out loud — explain your approach
- Start with brute force, then optimize
- Test with edge cases (empty, single element, negative)
- Time complexity: always mention Big O
